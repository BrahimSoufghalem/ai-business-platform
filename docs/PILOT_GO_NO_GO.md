# Pilot Go/No-Go Checklist

هذه القائمة هي بوابة إلزامية قبل إدخال أي بيانات عميل حقيقية أو تفعيل قناة خارجية. القرار الافتراضي **No-Go** حتى تكتمل البنود ويوقع أصحاب القرار على commit محدد.

## معلومات الإصدار

| الحقل             | القيمة |
| ----------------- | ------ |
| Commit SHA        |        |
| البيئة            |        |
| متجر Pilot        |        |
| تاريخ نافذة Pilot |        |
| مسؤول تقني        |        |
| مسؤول المنتج      |        |
| مسؤول الخصوصية    |        |

## البوابات التقنية

- [ ] CI أخضر على Commit SHA أعلاه.
- [ ] `pnpm pilot:gates` أخضر ولا توجد ثغرة production `high` أو `critical`.
- [ ] اختبارات tenant isolation وauthorization وRLS خضراء.
- [ ] trace موثق يربط `message → AI run → Tool Call → Order`.
- [ ] فشل Command Tool يتحول للموظف ولا يكرر الأثر.
- [ ] health live/ready وstructured logs و`X-Correlation-Id` متحقق منها.
- [ ] rate limit يعيد `429` و`Retry-After`؛ تشغيل API نسخة واحدة أو وجود limiter موزع.
- [ ] لا توجد أسرار في repository/history أو logs أو إعدادات العميل.
- [ ] migrations مطبقة على staging مع خطة forward-fix.

## البيانات والاستعادة

- [ ] بدأت التجربة ببيانات اصطناعية واجتاز seed إعادة التشغيل دون مضاعفة المخزون.
- [ ] نسخة احتياطية حديثة مخزنة مشفرة وبصلاحيات مقيدة.
- [ ] تجربة restore نجحت، وسُجل الزمن ضمن RTO المستهدف.
- [ ] RPO/RTO معتمدان من مالك Pilot.
- [ ] سياسة retention والحذف والتصدير معتمدة.
- [ ] شروط مزود AI ومكان المعالجة وعدم التدريب معتمدة.

## التشغيل والمستخدمون

- [ ] تم تدريب owner/manager على [دليل التدريب](PILOT_TRAINING.md).
- [ ] تم تدريب الموظف على claim/release/resume ومنع الرد المتوازي.
- [ ] تم اختبار تنبيه المخزون وHandoff wait وفشل Tool.
- [ ] توجد تغطية موظف وساعات دعم ومسار تصعيد واضح.
- [ ] feedback log جاهز ولا يسمح ببيانات شخصية.
- [ ] جولة tabletop للحوادث اكتملت.
- [ ] مسؤول النسخ، التنبيهات، الأمن ودعم المستخدم محدد لكل نافذة.

## معايير النجاح لأول يوم

املأ القيم قبل البدء:

| المقياس                    | الهدف/الحد | النتيجة | Pass |
| -------------------------- | ---------- | ------- | ---- |
| الطلبات الصحيحة End-to-End |            |         |      |
| أثر مكرر أو رصيد سالب      | 0          |         |      |
| P95 AI latency             |            |         |      |
| Handoff ضمن زمن الاستجابة  |            |         |      |
| Command Tool failures      |            |         |      |
| تكلفة AI اليومية           |            |         |      |
| P0/P1 مفتوحة               | 0          |         |      |

لا تستخدم أرقامًا غير متفق عليها أثناء التشغيل؛ الهدف يُملأ ويوقع قبل النافذة.

## شروط No-Go الفورية

- ثغرة `critical/high` غير مقبولة أو سر غير مدوّر.
- فشل العزل أو وصول مستخدم إلى متجر آخر.
- فقد بيانات، رصيد سالب، طلب/حجز مكرر أو كتابة AI خارج Tool.
- فشل restore أو غياب نسخة قابلة للقراءة.
- trace غير كافٍ لتشخيص رحلة كاملة.
- غياب مسؤول Handoff أو خطة incident.
- سياسة بيانات/مزود غير معتمدة.
- أي P0/P1 مفتوحة.

## القرار

اختر واحدًا فقط:

- [ ] **GO** — كل البنود مكتملة ولا توجد استثناءات غير مقبولة.
- [ ] **CONDITIONAL GO** — لا يُسمح إلا ببيانات اصطناعية؛ الاستثناءات موثقة أدناه.
- [ ] **NO-GO** — التفعيل محظور حتى إعادة المراجعة.
